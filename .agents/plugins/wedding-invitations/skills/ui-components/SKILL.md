# UI Components Skill

## Purpose

UI components should provide:
- consistency
- reusability
- scalability
- premium design quality

Components are the foundation of the visual system.

---

# Core Philosophy

Components should remain:
- modular
- lightweight
- reusable
- accessible
- responsive

Avoid creating one-off inconsistent UI patterns.

---

# Component Structure

Components must:
- have single responsibility
- remain composable
- avoid business logic

Prefer:
- clean props
- reusable APIs
- predictable behavior

---

# Design Consistency

All components must follow:
- shared spacing system
- shared typography
- shared color system
- shared radius system
- shared animation patterns

Consistency is critical.

---

# Styling Rules

Use:
- Tailwind CSS
- shadcn/ui patterns

Avoid:
- inline styles
- random spacing
- inconsistent shadows

---

# Responsive Rules

Every component must support:
- mobile
- tablet
- desktop

Mobile-first design is mandatory.

---

# Accessibility Rules

Components must:
- support keyboard navigation
- maintain readable contrast
- provide proper labels
- support screen readers when necessary

Accessibility is not optional.

---

# Animation Rules

Component animations should:
- remain subtle
- improve UX
- avoid distraction

Avoid:
- excessive motion
- performance-heavy effects

---

# Reusability Rules

Components should remain generic enough for reuse.

Avoid:
- tightly coupled components
- duplicated UI patterns
- template-specific component logic

---

# Performance Rules

Components must:
- minimize rerenders
- remain lightweight
- lazy load heavy content when necessary

Avoid oversized component architecture.

---

# Final Principles

Always prioritize:
1. consistency
2. reusability
3. accessibility
4. responsiveness
5. performance

Components should feel:
- premium
- clean
- modern
- lightweight
