# Dashboard Patterns Skill

## Purpose

The dashboard is the primary product workspace.

It should help users:
- create invitations
- edit content
- manage assets
- publish invitations

The dashboard must remain:
- intuitive
- lightweight
- mobile-friendly

---

# Core Philosophy

The dashboard should feel:
- calm
- clean
- guided
- modern
- emotionally warm

Avoid enterprise admin dashboard aesthetics.

---

# Layout Philosophy

Preferred structure:
- simple navigation
- focused content area
- lightweight controls
- clear hierarchy

Avoid:
- overcrowded sidebars
- excessive nested menus
- dashboard clutter

---

# Editor Layout Rules

Preferred editor structure:
- editing controls
- live preview
- responsive layout

Editing should feel immediate and smooth.

---

# Mobile Dashboard Rules

Dashboard must remain usable on:
- phones
- tablets

Prefer:
- collapsible panels
- bottom actions
- simplified navigation

Avoid desktop-only assumptions.

---

# Empty States

Empty states should:
- guide users
- feel friendly
- reduce confusion

Avoid generic placeholders.

---

# Loading States

Use:
- skeleton loaders
- smooth transitions
- lightweight loading patterns

Avoid blank screens.

---

# Interaction Rules

Dashboard interactions should:
- feel responsive
- provide feedback
- remain predictable

Avoid delayed UI responses.

---

# Performance Rules

Dashboard must remain:
- lightweight
- responsive
- smooth during editing

Avoid:
- heavy rerenders
- unnecessary animations
- large client-side state

---

# Final Principles

Always prioritize:
1. clarity
2. responsiveness
3. ease of use
4. mobile usability
5. smooth editing experience

The dashboard should feel:
- premium
- focused
- effortless
